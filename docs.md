# **Документация классов проекта "Нейро-символический решатель"**

Этот документ содержит подробное описание классов и методов системы. Проект построен по принципам SOLID и Clean
Architecture.

## **1\. Domain Layer (domain\_logic.py)**

Этот модуль содержит основные сущности математической логики. Все классы данных реализованы как dataclass и являются
неизменяемыми (frozen=True) для обеспечения безопасности при хешировании и сравнении, кроме Clause и структур
результатов, которые могут изменяться в процессе.

### **Term**

Представляет терм в логике предикатов (константу или переменную).

* **Атрибуты:**
    * name (str): Имя терма (например, "x" или "Сократ").
    * is\_variable (bool): Флаг, указывающий, является ли терм переменной.
* **Методы:**
    * \_\_str\_\_: Возвращает имя терма.

### **Predicate**

Представляет атомарную формулу (например, Human(Socrates)).

* **Атрибуты:**
    * name (str): Имя предиката.
    * arguments (List\[Term\]): Список аргументов (термов).
* **Методы:**
    * \_\_str\_\_: Возвращает строковое представление в формате Имя(арг1, арг2).

### **Literal**

Представляет литерал — предикат с возможным отрицанием (например, ¬Mortal(x)).

* **Атрибуты:**
    * predicate (Predicate): Предикат.
    * is\_negated (bool): Флаг отрицания (True если есть ¬).
* **Свойства:**
    * negation: Возвращает новый объект Literal с инвертированным флагом is\_negated.

### **Clause**

Представляет дизъюнкт (клоз) — дизъюнкцию литералов (например, ¬Human(x) ∨ Mortal(x)).

* **Атрибуты:**
    * literals (List\[Literal\]): Список литералов, входящих в дизъюнкт.

### **ProofStep**

Структура для логирования одного шага доказательства. Используется для генерации объяснений.

* **Атрибуты:**
    * step\_id (int): Уникальный номер шага.
    * description (str): Текстовое описание действия (например, "Резолюция между 1 и 2").
    * clause\_produced (Optional\[Clause\]): Клоз, полученный на этом шаге (если есть).
    * parents (List\[int\]): Список ID шагов-родителей, на основе которых получен текущий результат.

### **ResolutionResult**

Результат работы алгоритма резолюций.

* **Атрибуты:**
    * proven (bool): True, если доказательство успешно (найдено противоречие), иначе False.
    * proof\_log (List\[ProofStep\]): Полный журнал шагов доказательства.

## **2\. Resolution Engine (resolution\_engine.py)**

Символьное ядро системы. Отвечает за строгое математическое доказательство.

### **UnificationError**

Исключение, выбрасываемое, когда унификация двух предикатов невозможна.

### **ResolutionEngine**

Основной класс движка.

#### **solve(knowledge\_base: List\[Clause\], goal: Clause) \-\> ResolutionResult**

Основной метод доказательства.

* **Алгоритм:** Доказательство от противного (Reductio ad absurdum).
* **Аргументы:**
    * knowledge\_base: Список фактов и правил (аксиом).
    * goal: Целевое утверждение, которое нужно доказать.
* **Логика работы:**
    1. Инвертирует цель (¬Goal).
    2. Добавляет инвертированную цель в базу знаний.
    3. Пытается вывести пустой клоз (противоречие), применяя правило резолюции ко всем парам клозов.
    4. Возвращает результат с логом доказательства.

#### **\_resolve(c1: Clause, c2: Clause) \-\> List\[Clause\]**

Внутренний метод. Пытается применить правило резолюции к двум клозам.

* Ищет комплементарные пары литералов (например, P(x) и ¬P(Socrates)).
* Пытается унифицировать аргументы.
* При успехе возвращает список новых клозов (резольвент).

#### **\_unify(p1: Predicate, p2: Predicate) \-\> Dict\[str, Term\]**

Реализует алгоритм унификации (нахождения наиболее общей подстановки переменных).

* Возвращает словарь подстановок (например, {'x': Term('Socrates')}).
* Выбрасывает UnificationError, если унификация невозможна.

## **3\. LLM Service (llm\_interface.py)**

Слой абстракции для работы с языковыми моделями.

### **LLMProvider (Abstract Base Class)**

Интерфейс, который должны реализовать все адаптеры к LLM (OpenAI, YandexGPT, Ollama и т.д.).

#### **formalize(text: str) \-\> Tuple\[List\[Clause\], Clause\]**

**Задача Модуля 1\.**

* Переводит текст на естественном языке в формальную логику.
* Возвращает кортеж: (База знаний, Цель).

#### **explain(result: ResolutionResult) \-\> str**

**Задача Модуля 3\.**

* Принимает лог формального доказательства.
* Генерирует понятное текстовое объяснение на естественном языке.

### **MockLLM**

Заглушка для тестирования и демонстрации без API ключей.

* Имитирует работу LLM на примере задачи о Сократе.

## **4\. Main System (neuro\_symbolic\_solver.py)**

### **NeuroSymbolicSolver**

Класс-оркестратор (Application Layer). Связывает компоненты воедино.

#### **\_\_init\_\_(llm: LLMProvider, engine: ResolutionEngine)**

Использует Dependency Injection для получения экземпляров LLM и движка.

#### **process\_query(user\_text: str) \-\> str**

Выполняет полный цикл обработки запроса:

1. **Formalization**: Вызывает llm.formalize.
2. **Reasoning**: Вызывает engine.solve.
3. **Explanation**: Вызывает llm.explain.
4. Возвращает итоговый ответ пользователю.
